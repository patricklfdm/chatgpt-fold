# 0.2：原生卸载与重新挂载入口验证

## 阶段目标

0.1.x 的收尾基线是已合并的 **0.1.7**，提交 `5fc9f84c179eb5d09e8aa48057df873341d94fc3`。0.2 从验证原生控制入口开始：扩展保留轻量折叠条，由 ChatGPT 自己决定正文组件的卸载与恢复，沿用原站组件和交互。

**当前状态：尚未取得可调用的逐条回答挂载／卸载入口。** 此目录的观测工具不接入内容脚本，不代表深度折叠已实现。安装版本仍为 0.1.7；验证工具的独立版本不表示发布了 0.2 扩展。

入口必须同时满足：

1. 目标回答仍在当前可见范围，收起时原站自身移除正文，展开条仍可操作。
2. 展开时由原站恢复正文，复制、代码、引用等原生交互正常。
3. 不需要把目标先滚出屏幕，也不靠扩展保存旧 DOM 或 HTML 再塞回去。
4. 不影响邻近回答、正在生成的内容、展开上限和跨挂载的用户选择。
5. 另行测量确认内存净收益；DOM 断开、WeakRef 读不到和一次堆读数均不等于收益证明。

“滚到目标附近、等原站加载”只能证明导航协作，不能单独满足第 1 项。

## 已完成的公开代码调查

注册表的帮助文本将用途定位为 Codex Desktop UI；代码中也有共享的 ChatGPT 路由支持，因此不能断言整个模块永远不会被网页使用。可以确认的是：已追到的具体折叠动作不控制对话正文。

公开 runtime 导出内部模块加载器，不能以“没有挂在 window 上”为由断言内部模块绝不可达。但本次没有验证用户页面的模块实例、绑定 scope、版本一致性或可调用权限，也没有尝试调用它。

对 39 个公开脚本的有限检查没有命中用户页面已出现的 `data-talvt-turn-state` / `data-turn-key`。这说明样本尚未覆盖已知现代渲染路径，不能证明 ChatGPT 没有原生虚拟化。

结论：**将这条动作注册表线索降级为 UI 导航机制，下一步从实际页面的节点移除调用点反向定位。** 资源 URL、哈希及初始动作清单见 [native-entry-audit.json](research/native-entry-audit.json)。公开资源会随部署变化，哈希只说明此次读取的文本版本。

## 单条回答观测工具

文件：[experiments/native-lifecycle-probe.js](../experiments/native-lifecycle-probe.js)。在 DevTools 的页面 `top` Console 手动运行，不需要切换到扩展的隔离上下文。

工具记录折叠后所跟踪的正文包装节点是否仍连接、滚动时包装节点或回答根是否断开、同一消息是否以新根出现，以及初始祖先外壳在这些采样阶段是否连接。它不会查找或调用未知控制器，报告明确保留：

- `nativeMountEntry: "not-tested"`
- `reactUnmount: "not-proven"`
- `memoryBenefit: "not-measured"`

### 运行步骤

1. 等当前回答生成结束。在 Elements 中选中一条已完成回答的正文或其子元素；不要选整个 main、输入框或用户问题。所选元素通过 DevTools 的 `$0` 提供。
2. 切到 Console 的 `top` 上下文，复制并运行探针文件的完整内容。当前工具要求现代轮次明确为 `complete`，且目标具有可靠单消息身份；无法安全选择时返回原因。
3. 让目标留在视口里，手动收起它，再执行 `__CGF_NATIVE_PROBE_V1__.mark("folded")`。展开后执行 `.mark("unfolded")`。这两个标签只是人工阶段标记，实际状态以报告里的连接状态和布局信息为准。
4. 手动滚动使目标远离视口，执行 `.mark("away")`；再滚回去，执行 `.mark("returned")`。自动观测补充中间状态，不自动滚动或点击。
5. 完成后复制报告：

```js
__CGF_NATIVE_PROBE_V1__?.stop();
copy(__CGF_NATIVE_REPORT_V1__);
```

默认最长 90 秒、最多 120 个快照。提前停止、超限或页面环境改变后会清理监听与观察器；结束后可重新选择目标再运行。切换会话、替换 body、离开页面或出现生成信号时中止，以免把不同场景混为一次实验。

只在内存中保留一个有长度限制的消息身份用于重匹配，节点使用少量弱引用；不输出原始身份、正文、HTML、页面标题或 URL，不上传和持久化记录。报告只有固定枚举、数字和布尔值。DOM 观察本身有开销，因此不用于性能基准。

**DevTools 自己可能保留 `$0` 等选中节点。** 本工具不验证 GC，不把弱引用是否还能读取当作泄漏或释放结论。采样会合并快速变化，没有记录到断开不等于从未断开。屏幕内外的几何状态也是采样结果，不等同于原站的全部裁剪／可见性判断，不能反推出其预加载距离。

`summary` 中的断开／新根／持久祖先标志以回答根为范围。正文包装节点单独移除时，应检查 `originalBodyConnected` 等快照字段，不能因为回答根的汇总标志为 false 就排除正文虚拟化。包装节点仍连接时，其内部子树也可能已改变；本工具不逐节点追踪整条回答。

### 如何解释结果

| 观察 | 可以得出的结论 | 不能得出的结论 |
| --- | --- | --- |
| 收起后被跟踪的正文包装与回答根仍连接 | 这两个节点未在该采样时移出文档 | 内部重子树没有移除，或仅发生了 CSS 隐藏 |
| 正文断开、回答外壳仍连接 | 存在更小颗粒度的 DOM 移除 | React 组件已销毁或存在可调用的卸载 API |
| 原回答根断开，同一身份出现新根 | 发生了 DOM 替换／重建 | 所有旧对象均已回收 |
| 初始某层祖先在采样到的断开与恢复阶段均连接 | 该层是持久外壳的候选 | 整段时间从未断开、可安全放置按钮或它会永远保留 |
| 滚动后内容恢复 | 原站响应了某种可见性／导航条件 | 可以让仍在屏幕里的任意一条回答保持卸载 |

## 从结果定位实际执行入口

### 简便的第一步：当前页面的前端文件清单

未登录首页的公开资源样本没有覆盖用户正在使用的现代渲染器。先取得实际页面引用或资源记录中可见的公共静态脚本地址，可以补齐这个调查缺口，不需要先操作 DOM 断点。

文件：[experiments/renderer-asset-inventory.js](../experiments/renderer-asset-inventory.js)。操作只有三步：

1. 打开要检查的 ChatGPT 对话页和 DevTools 的 Console，保持页面的 `top` 上下文。
2. 粘贴整个脚本并运行。无须在 Elements 选节点，不用滚动、折叠回答或设置断点。
3. 运行下面一行，把复制的 JSON 报告提供给开发者分析：

```js
copy(__CGF_ASSET_REPORT_V1__);
```

该脚本读取 `document.scripts` 的外部地址和当前 Resource Timing 记录。只接受精确 HTTPS origin 与静态路径白名单：`chatgpt.com/cdn/assets/`、`chatgpt.com/_next/static/` 和 `cdn.oaistatic.com/assets/`，并要求 JS/MJS 文件路径。输出去掉 query/hash，拒绝凭据、非默认端口及其他路径和来源；不读取内联脚本、正文、消息身份、页面标题或会话内容。

最多检查最近 512 个 script 元素和最近 4096 个资源记录，过滤前单个候选最长 4096 字符，保留 256 个去重地址，每个输出地址最多 1024 字符；超出这些上限时标记 `truncated`。资源 API 不可用时仍输出已取得的 DOM 资源清单，并记录固定原因。脚本不会发请求、修改 DOM、添加计时器或观察器，也不会包装浏览器原生方法。它只把有界 JSON 字符串放在页面的 `__CGF_ASSET_REPORT_V1__` 变量中供复制。

**这是当前可见的资源清单，不是节点移除调用栈。** script 元素可能尚未执行，资源记录也可能已被清空或受缓冲区限制，因此 `truncated: false` 不代表覆盖了全部执行过的模块。`coverage: "current-records-only"` 和 `nativeEntry: "not-tested"` 会保留这一区别。取得地址后先分析实际脚本；若仍不足以定位控制条件，再使用下面的 DOM 断点。

### 需要同步调用位置时：DOM 断点

被动观测必须与源代码定位分开。MutationObserver 回调发生在 DOM 修改之后，在回调里读取调用栈不能得到原始移除者的同步调用栈。

Chrome 支持 DOM change breakpoints：在 Elements 对目标节点右键，选择 **Break on → Node removal**；对候选持久父壳可选择 **Subtree modifications**。它能在修改或移除该节点的代码处暂停。参考 [Chrome 官方断点文档](https://developer.chrome.com/docs/devtools/javascript/breakpoints/#dom-change-breakpoints)。

建议一次只检查一条已完成回答：

1. 先用观测报告确定更可能被移除的正文根或回答根，再设置一个对应的 DOM 断点。
2. 手动滚动触发原站移除。只查看实际暂停的位置、公开静态脚本 URL、行列号及必要的调用帧名称。
3. 若先停在 React 的通用提交代码，继续定位调用路径或控制渲染条件的模块；这个暂停点本身还不是可复用入口。
4. 记录它操作的是正文、整轮对话还是连续的窗口范围；核对重新挂载如何恢复，以及消息身份如何进入该流程。
5. 解除断点后恢复页面。断点与调试器会改变执行时序和对象保留，不在这个会话中判断内存收益。

只需要必要的公开代码位置与结构关系，不需要导出聊天文本、完整 props/store、会话响应、请求令牌或任意全局对象。先确认控制器的职责和适用范围，再设计调用实验，不修改输出型 `data-*` 属性来冒充控制接口。

## 接入现有折叠逻辑的门槛

| 检查 | 当前状态 |
| --- | --- |
| 找到用户当前渲染器实际执行移除的脚本 | 待真实页面证据 |

取得入口证据后才考虑最小页面侧桥接。跨挂载的展开意图可以沿用 0.1.x 的有界设计，但不能把“用户希望展开”变成“离屏 DOM 必须常驻”。若原站只能控制整段窗口，不能独立卸载可见回答，就应按真实能力调整方案，不将导航协作包装成深度折叠。

# 测试与验收

本文列出检查方法、预期行为和记录模板。**这些步骤不代表已经在你的 Chrome 或真实 ChatGPT 会话中执行。** 模拟页面通过也不能证明当前线上页面完全兼容。

## 检查层次

| 层次 | 检查内容 | 不能证明什么 |
| --- | --- | --- |
| 静态检查 | JavaScript 语法、清单与工程完整性 | 真实 DOM 匹配、交互和节省内存 |
| Node 测试 | 配置与可独立测试的逻辑 | Chrome 注入行为和实际页面兼容性 |
| 合成页面浏览器测试 | 受控 DOM 上的折叠、恢复和动态行为 | 线上生成状态、所有富内容和网站未来更新 |
| 真实页面手动验收 | 你的实际对话、模型输出和站点交互 | 所有账户、所有地区、所有未来版本 |
| 内存对照实验 | 指定环境与对话下的实际收益 | 对所有长对话都成立的节省比例 |

## 自动检查

在工程根目录运行：

```bash
npm test
npm run check
```

这两项使用 Node.js 20 或更新版本和工程自带脚本，不需要 npm 安装第三方依赖。

可选浏览器检查：

```bash
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

浏览器检查使用 `tests/fixtures/chat.html` 的合成内容。测试浏览器与真实个人 Chrome 的登录状态、扩展安装和线上 ChatGPT 页面相互独立。

如果当前执行环境无法安装或启动 Chromium，应记录为“未执行 / 环境阻塞”，不能把它写成通过。

## 真实页面手动验收

先只启用 ChatGPT Fold，暂时关闭其他折叠、隐藏或重排对话的扩展。加载最新源码后，在 `chrome://extensions` 重新加载扩展，再刷新 ChatGPT 标签页。

### 1. 首次进入长对话

1. 使用一段已有多轮助手回答的对话。
2. 打开扩展弹窗，确认启用、默认最近数量为 1、同时展开上限为 1。
3. 等待页面加载稳定，观察每条支持的助手回答。

预期：

- 用户问题仍完整显示。
- 支持的助手回答都有单行摘要与可操作按钮。
- 最新 1 条普通回答展开，其余普通回答折叠。
- 输入框、侧栏、导航和原有对话功能正常。
- 弹窗统计与页面状态相符；已识别但结构不支持时保留内容并报告未支持数量。完全缺少支持的角色标记时，应显示已识别 0 条并保留页面原样。

### 2. 展开与数量上限

1. 展开一条较旧回答。
2. 展开另一条较旧回答。
3. 收起当前回答。
4. 将上限改为 2，再展开两条普通回答。

预期：每次操作后，未受保护的展开回答数量不超过设置上限；再次点击可以收起。折叠 / 展开后，鼠标和键盘仍能操作控件。

### 3. 设置边界

分别验证最近数量 0、1、5，以及上限 1、2、5。尝试输入空值、负数、小数或超大值（如果控件允许），然后保存。

预期：无效输入被约束到有效范围；默认最近数量不大于上限；关闭后重新打开弹窗、刷新页面，偏好仍保留。聊天正文不应出现在 `chrome.storage.local`。

### 4. 正在生成

1. 保持折叠开启，发送一个会产生多段回答的普通问题。
2. 回答生成期间打开其他旧回答，尝试批量收起。
3. 等待生成结束，重复展开和收起。

预期：正在生成的回答不会被折叠操作中断；原站停止生成、继续生成和复制等功能保持正常。保护期间可以临时超过数量上限，结束后重新应用策略。

记录使用的生成入口和页面表现。若保护未识别到，应记录 DOM 适配问题，不要把长回答误认为“正常可折叠的旧回答”。

### 5. 文字选择与编辑

1. 在展开的助手回答中选择一段正文。
2. 保持选区，打开另一条回答或执行批量收起。
3. 清除选区，重复操作。
4. 在原站可编辑的区域进入编辑状态，验证输入、取消和保存。

预期：包含有效选区或编辑状态的回答暂时受到保护；不丢失选区或编辑内容；保护结束后可重新折叠。若当前页面没有可用的回答编辑入口，将该项标为“不适用”，不要伪造测试。

### 6. 内容类型

用已有的普通文本、长列表、表格、代码块、公式和图片回答分别展开 / 收起。

预期：内容恢复后显示正确，代码复制等原站操作可用；摘要保持单行，不因长链接或代码撑宽页面。未知富内容结构应保守保留显示。

### 7. 对话切换与动态内容

1. 从侧栏切换到另一段已有对话。
2. 新建对话并连续进行多轮交流。
3. 使用浏览器前进 / 后退。
4. 如账户界面提供回答分支切换，验证不同分支。
5. 删除或重新生成一条回答后，检查状态。

预期：新页面正确识别，不残留旧对话摘要；同一条回答不重复添加控件；页面移除的回答不继续计数；原站操作不报错。

### 8. 临时恢复与原生搜索

1. 先确认一条旧回答处于折叠状态。
2. 在扩展弹窗中临时恢复本页。
3. 使用 `Ctrl+F` / `⌘F` 搜索该回答中的词。
4. 完成阅读后继续折叠。

预期：恢复后可以搜索正文；恢复期间暂停自动折叠；继续折叠后按当前设置运行。注意恢复会重新增加同时渲染的内容。

### 9. 禁用、刷新和异常状态

1. 在弹窗中关闭启用开关，确认原内容恢复。
2. 重新开启，确认策略恢复。
3. 打开非 ChatGPT 标签页，再打开弹窗。
4. 重载扩展但尚未刷新 ChatGPT 页面时，检查弹窗提示；随后刷新页面重试。
5. 查看 `chrome://extensions` 的扩展错误，以及页面控制台是否出现与扩展有关的异常。

预期：不可用页面有明确提示；没有消息接收端时不会显示虚假的操作成功；刷新后恢复正常。

## 内存验证

折叠不删除原 DOM，也不卸载站点 JavaScript 状态。**页面变短、滚动更顺滑、DOM 节点减少、JavaScript 堆下降、进程内存下降是不同现象，应分别记录。**

### 对照条件

选择一段你经常卡顿的实际长对话。记录 Chrome 版本、操作系统、对话大致轮数、富内容类型和扩展版本。

尽量保持以下条件一致：

- 同一段对话、窗口大小、页面缩放和页面位置。
- 不在生成回答时测量，等待网络、图片和字体加载稳定。
- 关闭其他影响页面的扩展或保持两组设置相同。
- 测试过程中不要新增大量消息、切换模型或同时运行不同负载。
- 为每次冷加载提供相近的等待时间，至少重复 3 组对照，报告范围或中位数。

### 建议步骤

1. **基线 A：** 关闭 ChatGPT Fold 效果，重新加载同一段对话，等待稳定并记录。
2. **折叠 B：** 开启扩展，设置最近 1 条 / 上限 1，重新加载同一段对话，用相同条件记录。
3. **往返操作：** 在 B 中交替打开不同历史回答，完成约 20 次展开 / 收起，再记录。
4. **恢复检查：** 临时恢复所有正文，验证内容正确；继续折叠，再记录一次。
5. **清理检查：** 连续切换若干对话，检查计数是否回到当前页范围，以及是否出现持续增长趋势。

应使用分别重新加载的 A/B 结果进行主要比较；同一次页面加载中反复切换只能作为补充，因为先前分配的内存可能被浏览器缓存。

### 记录哪些指标

| 指标 | 在哪里看 | 如何理解 |
| --- | --- | --- |
| 标签页相关内存 | Chrome 任务管理器，通常可用 `Shift+Esc` 打开 | 更接近使用者实际压力，但可能包括缓存和共享进程影响 |
| JavaScript 内存 | 任务管理器的 JavaScript 内存列或 DevTools | 折叠不会主动删除站点 JS 状态，不保证下降 |
| DOM 节点数 | DevTools Performance monitor 等工具 | 原节点保留；少量新增扩展控件属预期 |
| 布局 / 绘制与 CPU | DevTools Performance / Performance monitor | 检查同类滚动或展开操作的渲染代价 |
| 响应与错误 | 实际滚动、点击、生成和控制台 | 节省资源的同时必须保证内容可用 |

Chrome 版本和平台可能改变工具菜单或列名。参考 [Chrome DevTools 内存问题指南](https://developer.chrome.com/docs/devtools/memory-problems)。

### 比较时的注意点

- DevTools 自身会改变页面性能；两组应使用相同的工具状态。可先用任务管理器做低干扰对照，再用 DevTools 诊断原因。
- 页面当前还持有的对象不会因为触发垃圾回收而自动释放；强制回收只适合诊断，且两组条件要相同。
- 浏览器释放了对象后，也未必立即把相同大小的内存返还给操作系统。
- 不要把 DOM 节点计数当成内存大小，也不要仅根据 JS 堆推算整个标签页占用。
- 有意保留的活动页面节点与“离开对话后仍被扩展引用的节点”应分开判断。用堆快照排查时，不要因看到一个 detached 节点就直接认定是扩展泄漏。

## 问题反馈建议

报告 Chrome 版本、扩展版本、复现步骤、设置值和弹窗计数。必要时提供已脱敏的页面结构或截图；不要把会话令牌、个人对话正文或完整账户数据提交到公共 Issue。

## 发布前验收记录

项目维护者应在每次发布时单独记录实际执行结果：测试时间、命令、环境、通过 / 失败 / 未执行，以及真实页面的覆盖范围。本文仅规定方法，不预填通过状态。

## 原问题复现

### 0.1.6：旧 body 保留与普通更新重复扫描

基线为已合并的 0.1.5：`7d69c4187dec9184730f0398bd7c6d864e20ed5f`。前轮分析在真实 Chromium 的合成页面中完成整段 `body` 替换后，等待 350 毫秒且不查询状态、不重扫、不触发交互，仍读到 3 条断开记录及指向旧 body 的观察目标。随后触发 `selectionchange`，才释放旧记录并切换观察器。这是一个有明确触发条件的旧树保留路径，不等于证明每条新消息都会泄漏。

旧实现的普通正文更新即使经过 120 毫秒合并，仍会执行全记录身份同步、全局 Stop / 生成标记检查和完整策略；普通 markup 替换还会触发全记录资格检查。下方的同环境版本对照记录了具体调用数量。

0.1.6 用只观察 `html` 直接子节点的观察器发现 body 更换，先释放旧引用，再自动连接新 body；body 暂时不存在时继续等待插入，暂停、禁用、页面挂起或销毁时停止。普通内层文字 / markup 更新只刷新受影响记录，身份、结构、显示、保护状态和交互变化继续走完整检查。新增维护套件不通过状态请求或手动重扫帮助恢复。

### 0.1.5：思考期间误锁旧回答（保留记录）

基线：0.1.4；合并到 `main` 的提交为 `6995dac`，文件树与本地已验证的 0.1.4 一致。在真实 Chromium 中使用未修改的基线源码、现代助手单元和模拟 Chrome API，分别插入停止按钮、新问题和新回答。通过 `requestAnimationFrame` 直接检查正文、按钮和徽标，不查询扩展状态或强制重扫。

原有 **13 组**第一帧回归全部通过，最先新增的 **5 组**目标关联回归全部失败，合计 **13 / 18 组通过**：

| 场景 | 基线的实际表现 |
| --- | --- |
| Stop 先出现，新问题和新回答尚未出现 | 第一采样帧中旧回答按钮已经被禁用，徽标为“生成中” |
| 新问题已出现、Stop 随后出现，但新回答尚未出现 | `keepRecent: 0` 下已折叠的旧回答被重新展开并禁用按钮 |
| 新回答出现前取消请求 | 取消前的思考等待期间，旧回答已经被错误保护 |
| 思考期间卸载末尾回答并重新挂载历史 | “生成中”错误转移到更早的历史回答 |
| 旧回答具有明确局部重新生成标记 | 除对应回答外，未生成的最后一条回答也被全局 Stop 错误锁住 |

原因是 `streamingElements()` 把任何有效、可见的全局停止按钮直接关联到当前已登记的最后一条回答。停止按钮本身只说明请求在进行，不能证明这条旧回答正在生成。0.1.5 改为等待确认新增回答后关联目标，并保留独立的局部生成标记判断。

0.1.5 修复后第一帧套件共 **20 组**，其中 **7 组**针对该问题，全部通过。后加的身份接续与下一次请求两组没有计入上述 0.1.4 基线失败数量。

### 0.1.4：展开选择丢失（保留记录）

基线：0.1.3；合并到 `main` 的提交为 `76ef599`，与本地已验证提交 `26dd21f` 的文件树一致。在真实 Chromium 中使用现代助手单元结构，通过控制栏展开回答，再模拟站点卸载 / 重新挂载或追加回答。断言期间不查询扩展状态，也不手动触发重扫。

| 场景 | 基线的实际表现 |
| --- | --- |
| 手动展开 A，将它卸载后以同一消息身份重新挂载 | 返回后的第一帧已经折叠，原选择丢失 |
| 上限 3，只有 A、B 展开，再追加 C | A、B 在第一帧被收起，即使三项仍在上限内 |
| 隐藏同一对话中的时间线，再重新显示 | 重新发现节点后丢失原展开选择 |
| 已展开的根节点改成另一条消息 | 新消息错误继承原节点的展开状态 |

原因是展开标志只存于 DOM 登记记录：记录释放时选择丢失，重新登记默认关闭；确认新回答后又调用会清空旧选择的最近重置。只修改上限时也会重置所有选择。

新增展开状态回归的 **13 组**在该基线上有 **9 组失败、4 组通过**。这些结果证明用例能检测状态丢失与错误继承，不是对线上页面的性能测量。

此前的闪现问题已在 0.1.2 基线 `a353367` 上复现；当时新增的 13 组首帧回归有 10 组失败，0.1.3 修复后通过。本次继续运行这套回归，确保恢复展开选择时不重新引入“先显示再折叠”。

以下为 600 条完整 DOM、只展开最近 1 条、主动 GC 后的三轮中位数；不加载扩展的基线显示全部内容。堆单位为 MiB（1,048,576 字节），两类堆指标不能当成完整标签页内存直接相加。

### 持续追加与旧节点移除

固定挂载 20 条、累计创建 1200 条时，0.1.5 与 0.1.6 都保持 20 条记录、20 个控件、1 个展开选择，断开记录为 0；0.1.6 的两个待处理队列在检查点均为 0，记录释放累计为 1180。两版 GC 后 DOM 节点都是 3709、布局对象都是 403。

该终点 JS 堆三轮中位数为旧版 1.611 MiB、新版 1.594 MiB；新版范围 1.593605–1.594791 MiB。但新版初始 20 条时中位数约为 1.361 MiB，期间仍有小幅增长，不能宣称严格平台或证明所有泄漏都不存在。可确认的是，这个站点确实移除旧节点且不另存历史数据的合成条件下，扩展的当前记录没有随累计 1200 条一起增长。

基准没有模拟 ChatGPT 的内部数据保留，没有读取真实会话，也没有测量实际 Chrome 标签页总内存。复现参数、指标定义及限制见 [MEMORY.md](MEMORY.md)。

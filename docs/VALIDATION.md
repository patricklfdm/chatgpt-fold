# 本次交付的验证记录

版本：0.1.4。验证环境：Linux、Node.js v24.22.1、Linkedom 0.18.15、Chromium 153.0.8010.0。

这份记录区分策略与 DOM 检查、真实 Chromium 中的合成页面回归、使用者反馈，以及尚未执行的真实扩展和线上页面完整验收。

## 页面证据与适配范围

使用者提供的只读结构报告确认，选中的回答位于顶层 `conversation` 文档，旧作者 / turn / Markdown 类等已检查标记均为 0；祖先包含 `data-chatgpt-search-message-ids` 与 `data-talvt-turn-state`。这排除了“选中回答位于 iframe 或 Shadow DOM”对这条回答的解释，也说明旧选择器不足以覆盖该页面。

探针有意不导出 unit key 等原始值，因此报告没有证明新 unit key 或助手正文属性不存在。0.1.2 依据上述线索和[架构说明中的作者实测资料](ARCHITECTURE.md#页面结构与识别边界)加入新页面家族规则，使用者确认已成功识别且折叠正常工作。0.1.3 经 [PR #1](https://github.com/patricklfdm/chatgpt-fold/pull/1) 合并后，使用者进一步确认快速滚动时的全文闪现消失。

本次反馈是：手动展开的回答滚出屏幕再返回会被收起；新回答出现时，旧回答也会在未超上限时被收起。下面的自动测试使用合成结构，验证 0.1.4 对展开选择的保留；该修复在使用者实际会话中的效果仍待确认。之前版本的成功反馈不代表所有生成与富内容交互均已验收。

## 原问题复现

基线：0.1.3；合并到 `main` 的提交为 `76ef599`，与本地已验证提交 `26dd21f` 的文件树一致。在真实 Chromium 中使用现代助手单元结构，通过控制栏展开回答，再模拟站点卸载 / 重新挂载或追加回答。断言期间不查询扩展状态，也不手动触发重扫。

| 场景 | 基线的实际表现 |
| --- | --- |
| 手动展开 A，将它卸载后以同一消息身份重新挂载 | 返回后的第一帧已经折叠，原选择丢失 |
| 上限 3，只有 A、B 展开，再追加 C | A、B 在第一帧被收起，即使三项仍在上限内 |
| 隐藏同一对话中的时间线，再重新显示 | 重新发现节点后丢失原展开选择 |
| 已展开的根节点改成另一条消息 | 新消息错误继承原节点的展开状态 |

原因是展开标志只存于 DOM 登记记录：记录释放时选择丢失，重新登记默认关闭；确认新回答后又调用会清空旧选择的最近重置。只修改上限时也会重置所有选择。

新增展开状态回归的 **13 组**在该基线上有 **9 组失败、4 组通过**。这些结果证明用例能检测状态丢失与错误继承，不是对线上页面的性能测量。

此前的闪现问题已在 0.1.2 基线 `a353367` 上复现；当时新增的 13 组首帧回归有 10 组失败，0.1.3 修复后通过。本次继续运行这套回归，确保恢复展开选择时不重新引入“先显示再折叠”。

执行入口：`node tests/browser-smoke.cjs --mode=injected`，通过 `CHROME_PATH` 指定本地 Chromium 可执行文件。也可使用 `npm run test:browser -- --mode=injected`。

结果：**27 组通过，0 组失败，退出码 0**。运行环境为 Chromium **153.0.8010.0** 与 Playwright，页面为工程自带的合成聊天内容。

该模式执行实际页面脚本、CSS 和浏览器 `MutationObserver`，覆盖折叠 / 展开、动态内容、保护条件、清理与诊断。Chrome 扩展 API 由测试脚本模拟，所以这些通过结果不验证真实扩展权限、隔离环境注入或 Chrome 扩展消息管道。

本次重新执行原有的 27 组回归，并扩展同一路由 `body` 替换的场景：重扫恢复后，手动展开的旧回答通过相同实际消息 ID 保留选择，之后新增回答仍可按名额加入。旧节点引用与临时登记编号被释放。这套测试保留 0.1.1 的 21 组场景，包含非 `article` 容器、祖先重扫、暂停 / 禁用重扫和诊断隐私；另含 0.1.2 新增的 6 组场景：

- 仅使用现代标记的对话初始化、展开上限、原节点 / 原生事件保留和用户提问可见性。
- 消息标识与助手正文的补充识别及分组。
- 现代用户标记、混合容器和冲突角色的保护。
- 仅属性变化时的自动重新识别；测试不通过状态查询帮助恢复。
- 隐藏工作区的 class / style / hidden / aria-hidden / role / 时间线标记切换，以及 `display:contents`、屏幕外和可见 `inert` 内容的处理。
- 输入区内英文 / 中文 Stop、隐藏或无关 Stop 的排除，以及 composer 标记单独变化。

本次回归未出现页面脚本错误或持续的自触发 mutation 循环；通过仍不构成所有真实站点交互或长时间内存表现的证明。

在具备 Chromium 的电脑上，可以复跑注入模式：

```bash

npx playwright install chromium
npm run test:browser -- --mode=injected
```

## 历史挂载第一帧回归：注入模式通过

执行入口：`node tests/browser-first-paint.cjs`，等同于 `npm run test:paint`；通过 `CHROME_PATH` 指定本地 Chromium。此入口仅运行显式的注入模式，Chrome API 由测试模拟。

结果：**13 组通过，0 组失败，退出码 0**。

该测试在页面修改 DOM 后的下一次 `requestAnimationFrame` 读取实际计算样式、布局盒与控制栏状态，并继续采样后续帧，检查是否短暂展开。断言期间不调用状态查询、控制器 `flush()` 或重扫接口。每组使用独立的合成页面，网络请求被拦截，不读取用户真实对话。

覆盖范围：

- 旧回答首次挂载、以相同消息身份重新挂载，以及旧根节点复用于另一条消息。
- 已折叠正文后续补齐、整段正文子树替换和控制栏恢复。
- 实际末尾回答卸载后继续加载历史、整段历史窗口替换、已知末尾重新挂载后的正常新增，以及隐藏时间线重新显示。
- 助手标记改成用户标记时立即恢复原内容。
- 默认最近数量为 0 时的新生成，以及已折叠回答内部新增明确生成标记。
- 站点 CSS 隐藏的生成标记不误触发展开。
- 暂停或禁用折叠时，新挂载内容保持可见。

这些结果验证已启动扫描器对受支持结构的更新时序。它们不验证内容脚本冷启动之前的画面、尚无可靠作者标记的 DOM、真实 MV3 注入或内存节省。

## 展开状态保留回归：注入模式通过

执行入口：`node tests/browser-open-state.cjs`，等同于 `npm run test:state`；通过 `CHROME_PATH` 指定本地 Chromium。此入口使用实际 DOM、CSS 和 `MutationObserver`，Chrome API 由测试模拟。

结果：**13 组通过，0 组失败，退出码 0**。

用例通过控制栏建立真实的展开选择，在页面更新后的第一帧及后续短时间内检查正文布局与折叠状态。断言不通过查询扩展状态或手动扫描帮助恢复；不访问用户真实会话。覆盖内容包括：

- 同一消息卸载 / 重新挂载、隐藏时间线重新激活时恢复展开，且不把滚动当作新的展开操作。
- A、B 已展开，上限 3 时追加 C 保留三项；继续增加才淘汰最早项。
- 已卸载的项占用名额并参与淘汰；随后即使腾出名额，已淘汰项返回也不自行打开。
- 主动收起、收起全部、展开最近及对话切换，均正确处理已卸载的选择。
- 只改上限时保留较新的选择；先缩小再增大不会恢复淘汰项。
- 内部一致消息标识可恢复选择；同一位置型 unit key 被另一条回答使用时不能继承旧选择。
- 已知根节点换成另一消息、多个节点给出同一消息身份，以及没有消息 ID 的新节点，不错误传播展开状态。
- 同一活动节点晚到的消息 ID 在身份提示未变时可接续原展开顺序；未知节点换了 unit / turn 提示再获得新 ID 时，不继承旧选择。
- `keepRecent: 0` 时，临时生成保护不会转成长期展开选择，也不会无故清除之前的手动选择。

这些用例检查状态与名额规则，不测量内存节省。跨卸载的展开选择只保存标识和顺序；测试通过也不证明所有真实页面都会提供可用的消息身份。

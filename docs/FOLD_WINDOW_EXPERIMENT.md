# 0.2 第一阶段：折叠与原生窗口对照

本实验接续 [原生虚拟化源码调查](NATIVE_VIRTUALIZER_FINDINGS.md)。先验证折叠高度与原站挂载集合的关系，再决定是否进入原生正文条件挂载的适配。

**这是同页折叠样式对照，不能作为卸载扩展的基线，也不能直接证明标签页内存净收益。** 安装版本仍为 0.1.7；实验脚本独立运行，不加入扩展清单。

## 要回答的问题

1. 同一条轮次处于同一阅读位置时，折叠样式生效是否对应更多连接的原生轮次外壳和正文元素？
2. 显示正文后，挂载集合是否收缩？切回折叠后，计数能否恢复？
3. 当前页面是否存在范围迟滞、持续变化或位置失配，使这轮比较不能解释为稳定的同页响应？

原站的渲染集合是连续窗口与额外保留轮次的并集，且旧范围已经包含新需求时可能继续保留旧范围。因此，这里不强制刷新窗口，不滚去很远的位置，也不把 A、B 当作两个独立冷启动样本。

## 为什么不使用“临时恢复本页全部回答”按钮

现有 `restore` 命令调用 `stopActive()`，会清空展开意图；`resume` 又按 `keepRecent` 重新初始化。用它们做自动对照会改变用户选择。

本探针只临时改动扩展自己的 `html[data-cgf-active]`。正文的折叠 CSS 只在该值等于 `true` 时生效；旁路时，原站自己的布局样式自然恢复，扩展控制条按现有规则隐藏。它不写设置，不调用控制器，不主动清空展开意图，也不使用 `display:revert!important` 去覆盖原站布局。

| 阶段 | 折叠样式 | 扩展控制器 | 含义 |
| --- | --- | --- | --- |
| `A_folded` | 正常生效 | 持续运行 | 当前折叠状态 |
| `B_css_bypassed` | 临时旁路 | 持续运行 | 展示当前原生内容，隐藏折叠按钮 |
| `A_restored` | 恢复生效 | 持续运行 | 观察切回后的结果 |

B 中仍有扩展的观察器、记录和控件 DOM，只是控件不显示。不能把 B 叫作“扩展已暂停”“未安装扩展”或“原站内存基线”。没有稳定消息身份的展开意图，仍可能受既有原生重挂载处理影响；不主动清空选择，不等于对任何页面结构都能承诺精确恢复所有临时状态。

## 为什么新版区分切换和采样

一次真实页面的 `0.2.0-fold-window.1` 报告取得了稳定的 A 阶段数据，但进入 B 后，在第一份 B 样本前以 `answer_content_changed` 中止。旧版将滚动容器内任一助手正文的子节点增删或文本节点更新都作为中止条件。该报告没有记录触发变化的类型或所属轮次，无法判断是原站在显示时重建组件、真实内容改动，还是同一批次还有生成信号。它确认了折叠基线；没有 B 数据可以比较挂载规模或内存。

`0.2.0-fold-window.2` 只在 **B 和 A′ 切换样式后、首份样本前** 放宽一个条件：变化发生在可唯一归属的已登记、已完成回答中，而且该次子节点增删直接涉及的全部节点都是元素。每次遇到合格变化后重新等待，直到距最后一次变化至少 1.25 秒；每阶段仍至少等待 6 秒，最多为这种变化额外等待 4.5 秒。持续变化时以 `body_never_settled` 中止。

直接修改文本节点、直接增删文本节点或归属不清的正文更新仍会中止；A 起始阶段和各阶段采样期间也沿用严格条件。同批出现生成信号时优先报告生成。探针不读取正文、计算文本哈希或保存文本旧值，所以不能证明元素替换前后的内容相同。只要容纳过这类变化，后续即便取得稳定数据，也只按结构观察解释。

## 在真实页面运行：一次粘贴，无须选择节点

文件：[experiments/fold-window-probe.js](../experiments/fold-window-probe.js)。可在 VS Code 打开后全选复制，或在 GitHub 文件页复制源代码，不需要下载附件。

1. 等回答生成结束，确保 ChatGPT Fold 已启用。滚动到能完整看到几条旧回答折叠条的位置。
2. 打开 DevTools 的 Console，选择页面 `top` 上下文。把脚本完整粘贴并运行；不需要在 Elements 选中 `$0`。
3. 保持页面不操作，约 30 秒。Console 会依次提示 A、B、A；每阶段至少等待 6 秒，再以 1.5 秒间隔采集 3 个样本。等待结构稳定和位置对齐可能增加时间，总时限为 90 秒。
4. 出现“CGF 对照结束”后执行下面一行，把复制的 JSON 报告提供给开发者：

```js
copy(__CGF_FOLD_WINDOW_REPORT_V1__);
```

若上一份 `.1` 报告在 B 首次采样前中止，只需从上面的文件复制 **`.2` 新脚本再运行一次**。结束后确认报告中的 `probeVersion`；无论完成或中止，提供这一次的报告即可，不需要反复重跑或在 Elements 中选节点。

需要提前停止时：

```js
__CGF_FOLD_WINDOW_PROBE_V1__?.stop();
```

不要在一轮测量中切换扩展设置、发送消息、滚动页面、调整 DevTools 分栏或缩放窗口。发生这些变化时，探针会停止，不能把提前结束的数据当成完整对照。重新运行会清除上一轮结果，避免运行途中误复制旧报告。

## 如何保持同一位置

脚本自动选择一个完整可见的折叠条，使用其外层原生 `data-turn-key` 作为语义锚点。该轮次必须唯一、已完成，并包含唯一的已登记助手回答。

它只在内存中保存一个有长度上限的身份字符串和最初的相对视口偏移。切换样式后，重新定位同一轮次并调整滚动位置，让轮次顶端保持原来的偏移；不使用会随重挂载变化的扩展记录编号。

相同的 `scrollTop` 不等于相同消息位置。样本中的滚动像素可能变化，只要锚点仍是同一轮次且偏移误差在 2 px 内，才继续采样。锚点丢失、身份不唯一、最近滚动祖先变化或无法对齐时停止。

每次采样还会验证：A 的直接正文容器确实被隐藏，B 中正文确实恢复布局。只看 `data-cgf-collapsed` 标记不足以证明处理生效。

## 字段怎么读

| 字段 | 含义 |
| --- | --- |
| `outcome` | 流程是否完成；`completed` 本身不保证所有阶段稳定 |
| `summary.mode` | `strict`：完整稳定且未容纳正文变化；`settled-descriptive`：容纳过结构变化，之后采样稳定；`unstable`：采样完成但计数或几何不稳；`incomplete`：未完成三阶段采样 |
| `summary.comparisonValid` | 仅 `strict` 为真，表示本次同页结构对照通过探针检查；不代表已证明内容完全相同或内存净收益 |
| `phases[].condition` | 折叠样式生效或旁路；两个条件下扩展都运行 |
| `phases[].bodyChanges` | 本阶段过渡期容纳的结构变化批次等信息，不含正文或节点身份 |
| `trigger` | 因正文变化中止时，用固定枚举描述发生阶段、变化类型及其相对锚点的位置；不能据此识别具体页面组件 |
| `counts.nativeTurnWrappers` | 活动滚动容器内不重叠的、连接着的原生轮次外壳数 |
| `counts.registeredAnswers` | 同一容器内活动的扩展回答根数量 |
| `counts.nativeTurnElements` | 原生轮次子树元素数，排除扩展控件及其子树 |
| `counts.extensionElements` | 上述轮次中的扩展控件元素数 |
| `counts.assistantBodies` | 原生助手正文标记数量，不因折叠而忽略仍连接的正文 |
| `counts.markedCollapsedAnswers` / `markedExpandedAnswers` | 当前 DOM 的逻辑折叠标记数量；不是私有 `openIntents` 的读取结果 |
| `counts.documentElements` / `scopeElements` | 整个文档／滚动容器的元素数，包含相关扩展元素；不是全部节点或全部原生内存 |
| `anchor` | 锚点匹配、位置误差、轮次高度以及实际正文布局状态；不包含身份 |
| `jsHeapEstimate` | `performance.memory` 可用时的估计；不提供时为 `null` |
| `summary.foldedCountsRecovered` | 严格对照下，A′ 的四项结构计数是否与 A 相同 |
| `summary.restoredFoldedMinusBypassed` | 严格对照下 A′ 减 B 的结构计数差；其余模式为 `null` |

`countsStable` 要求同阶段的轮次、回答、正文和原生元素数量一致。`geometryStable` 还检查阶段内滚动高度、滚动位置和锚点高度变化不超过 2 px。未通过时保留原始样本，但不输出差值结论。

以下读法才与实验范围一致：

- A′ 比 B 多：本轮同页切换中，折叠对应更多连接的轮次／正文；真实内存增减仍待判断。
- 三阶段数量相同：本轮未观察到收缩或扩大；可能有范围迟滞、保留项或初始窗口历史影响，不能据此否定高度效应。
- A′ 与 A 不同：存在未恢复的结构差异；应结合各阶段稳定性和几何分析，不能直接称为内存泄漏。
- `settled-descriptive`：可以并列查看三阶段 `medianCounts`，描述同一锚点在各阶段稳定后有几条已挂载回答。即便计数不同，也不能将全部差异归因于折叠样式，或解释为等量的内存变化。
- `unstable` / `incomplete`：先看哪一阶段未稳定或没有样本，不用零散数字估算收益。

## 内存测量边界

真实页面脚本不访问私有 React 实例，不强制垃圾回收，不取得 Chrome 任务管理器数据。报告固定保留：

- `tabTotalMemory: "not-measured"`
- `gc: "not-forced"`
- `netMemoryBenefit: "not-established"`

`performance.memory` 是非标准、可能不完整或陈旧的 JS 堆估计。它不包括完整的 DOM、布局、图片、GPU 和标签页进程内存；单次下降不能证明本操作释放了对应数量的总内存。参见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/Performance/memory)。

需要评估真实页面净收益时，再单独采集 Chrome 任务管理器的 Memory footprint 与 JavaScript memory，并使用相同位置和条件重复比较。两列分别描述操作系统内存与 JS 堆，不能混用或简单相加。参见 [Chrome 内存排查文档](https://developer.chrome.com/docs/devtools/memory-problems)。本地自动化浏览器无法读取用户正在使用的另一台 Chrome 的这些指标。

## 容量、清理和恢复

一次运行最多检查 50,000 个文档元素、64 个登记回答、128 个原生轮次候选和 30,000 个原生轮次子树元素；锚点身份最长 192 字符。单批超过 2,048 条变动记录时以 `mutation_batch_limit` 停止；单条子节点增删涉及超过 256 个直接子节点时不予放行。

有界采样只保留数字和固定枚举；DOM 检查在同步辅助函数中完成，异步等待之间不保存回答节点、NodeList 或 MutationRecord。body、html 和滚动容器使用弱引用。没有网络请求、正文读取、HTML 副本、存储写入或运行时模块导入。会话路由只在内存中比较，不输出 URL。

在生成、页面隐藏、会话或 body 变化、滚动容器变化、用户输入以及门控被外部修改时停止。只在门控仍等于本探针写入的独占值时恢复为 `true`；用户中途停用扩展后不会被自动重新启用。

正常结束时尝试按原锚点恢复位置；用户主动滚动或切换会话后，不强行拉回旧位置。`cleanup.scroll` 区分已对齐、请求恢复、数值退回、用户操作后跳过和无法恢复。位置恢复请求不等于异步布局已经永久稳定。

结束和中止都会清理探针的监听、观察器和计时器。90 秒限制依赖浏览器事件循环能够继续运行，并非对已卡死页面的抢占机制。

## 常见未完成原因

| `reason` | 处理方式 |
| --- | --- |
| `extension_not_active` | 确认当前页启用了扩展并已出现折叠条 |
| `no_visible_folded_answer` | 滚到几条完整可见的旧回答折叠条处再运行 |
| `completion_unconfirmed` / `generation_active` | 等待生成结束；只接受明确完成的轮次 |
| `ambiguous_anchor` / `anchor_lost` | 当前结构或重挂载无法可靠匹配；保留报告用于适配分析 |
| `css_exposure_unconfirmed` | 样式实际效果不符合 A/B 条件；不能当成有效对照 |
| `external_gate_change` / `fold_policy_changed` | 扩展状态或折叠策略在实验中改变；探针尊重外部操作 |
| `viewport_changed` / `scroller_changed` / `alignment_failed` | 测量期间尺寸或滚动关系变化，未满足同一位置条件 |
| `answer_content_changed` | 出现不能纳入本次对照的正文变动；结合 `trigger` 判断发生在切换期还是采样期。它不一定表示用户编辑过文字 |
| `body_never_settled` | 切换后的合格结构变动持续到等待上限，未取得要求的平静间隔。保留这次报告即可 |
| `element_limit` / `answer_limit` / `turn_limit` / `native_element_limit` | 当前页面超过研究脚本的容量范围，不扩大上限强行运行 |

## 本地可重复验证

```bash
npm run test:fold-window
```

测试使用真实 Chromium 和合成页面，在独立 CDP execution world 中加载扩展内容脚本；Chrome API 明确模拟。页面世界的探针不能读取隔离世界中的控制器。这个环境用于检查跨世界 DOM 协作，不证明真实 MV3 扩展安装或用户页面已经验收。[Chrome 内容脚本隔离世界说明](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

合成窗口依照真实 DOM 的测量高度选取行，可选择是否保留已经覆盖新需求的旧范围。它不读取探针阶段来伪造计数，也不执行下载的 ChatGPT 代码。全量 DOM 场景用作对照。

本地 CDP 测量可以另记主动 GC 前后的 JS 堆、嵌入器堆、DOM 计数和布局对象数。它们仍是部分指标，不能相加得到标签页总内存。单次合成样本用于验证机制和计数解释，不向真实站点外推收益百分比。

### 本次修订验证（`.2`）

在 Chromium 153.0.8010.0、Node.js 24.22.1 下，28/28 组探针回归、3/3 个合成对照通过。按原始时序运行的一组取得了 `strict` 结果。另一个用例在 B 和 A′ 切换期替换包含不同文字的元素：9 个样本全部取得，结果为 `settled-descriptive`，严格差值为 `null`。直接文本变动、首个样本后的元素替换、持续结构变动及同批生成信号均保持中止。这些是合成页面验证；真实页的 B 数据仍需单独采集。

### 已执行结果（`.1` 历史基准）

2026-11-05：`0.2.0-fold-window.1` 在 Node.js 24.22.1、Chromium 153.0.8010.0 下，**23/23 组探针回归与 3/3 个合成对照通过**。原始记录见 [fold-window-v0.2.0.json](benchmarks/fold-window-v0.2.0.json)，包含该次执行源码、fixture、探针和测试驱动的 SHA256。一次完整探针使用原始等待时间，最后样本为 27,097 ms；异常路径另使用明确标注的缩短等待副本。以下数字属于当次合成实验。

合成列表包含 120 轮、800 × 720 px 滚动视口和 2 条窗口外缓冲；扩展设置为 `keepRecent: 0`、`maxExpanded: 3`，用于隔离高度效应。这不是用户真实页面或默认设置下的测量。

| 合成场景 | 挂载回答数：A → B → A′ | GC 后布局对象数：A → B → A′ |
| --- | --- | --- |
| 根据实际测量高度选择窗口 | 12 → 5 → 12 | 143 → 721 → 143 |
| 旧范围包含新需求时保留旧范围 | 12 → 12 → 12 | 143 → 1715 → 143 |
| 全部轮次一直挂载 | 120 → 120 → 120 | 1331 → 17051 → 1331 |

完整探针在第一种场景取得的原生轮次元素数为 **960 → 400 → 960**，均排除了扩展控件子树；三个阶段计数、几何稳定，锚点相同，结束后门控和位置恢复，探针资源清理完成。全量 120 行属于直接控制的本地合成基准，不绕过真实页探针的 64 条回答限制。

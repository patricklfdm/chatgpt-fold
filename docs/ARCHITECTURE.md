# 架构说明

## 目标与范围

ChatGPT Fold 0.1.0 先实现逐条回答折叠。目标是在保留随时展开能力的前提下，限制同时参与布局和绘制的回答数量。

使用者将内存占用置于首位，因此实现需要避免引入第二份完整聊天记录、HTML 字符串快照、离屏 DOM 树或大量持久缓存。本版选择较保守的 DOM 可见性控制；真实收益由测量确认。

本版不实现视口虚拟化，不修改 ChatGPT 的服务端对话，不接管站点的 React 渲染，也不读取内部 store、Fiber 或私有接口。

## 技术组成

| 文件 | 职责 |
| --- | --- |
| `manifest.json` | Manifest V3、站点匹配、内容脚本顺序、弹窗和 storage 权限 |
| `src/shared.js` | 默认配置、输入归一化，以及可独立验证的通用逻辑 |
| `src/adapter.js` | 查找助手回答、选择可折叠区域、检查页面保护条件 |
| `src/content.js` | 初始化与增量发现、折叠 / 展开状态、事件处理、弹窗通信、清理 |
| `src/content.css` | 单行摘要、按钮、主题适配和隐藏规则 |
| `src/popup.*` | 偏好编辑、当前页状态、临时恢复和批量操作 |

代码使用原生 JavaScript、CSS 和 Chrome 扩展 API。运行时不需要打包器、框架或远程依赖。

## 折叠机制

页面适配器以 `[data-message-author-role="assistant"]` 作为主要识别依据。该属性来自当前实现假设，不属于 OpenAI 对外承诺的扩展接口。

对支持的回答，扩展为其添加小型控制栏，并给原有的直接内容容器添加折叠样式。收起时使用 `display: none`；展开时移除扩展自己的隐藏条件。原有节点保留在原来的 DOM 关系中，站点的事件处理和组件状态仍由站点维护。

原站结构无法明确识别时，扩展应保留内容显示。不能把一个不确定的大范围容器直接隐藏，以免连输入框、用户问题或整段页面一起收起。弹窗中的未支持数量帮助定位这类适配问题。

### 为什么保留原节点

原站框架可能仍持有节点和组件引用。将节点移出、替换成自行恢复的 HTML 或删除后重建，会增加后续生成、分支切换、复制按钮等功能失效的风险。

初版通过添加控件和修改可见性来降低侵入程度。它仍然需要真实页面验证；浏览器扩展对第三方应用 DOM 的修改始终受页面版本影响。

### 为什么这不等于卸载内容

`display: none` 使隐藏元素不产生正常的布局盒（见 [MDN 的 display 说明](https://developer.mozilla.org/en-US/docs/Web/CSS/display)），但不会删除 DOM 对象，也不会释放仍被站点引用的回答数据。图片解码缓存、字体、浏览器内部资源、React 状态及 JavaScript 堆的回收时机也不能由这个开关直接保证。

因此，内存分析必须分开观察：

- **渲染工作与渲染相关内存：** 折叠可能产生收益，需要测量。
- **DOM 数量：** 原内容仍存在，不应声称已删除或大幅下降；扩展控件还会增加少量节点。
- **JavaScript 堆：** 未主动卸载站点对象，不保证下降。
- **Chrome 标签页 / 进程总内存：** 受多种分配与缓存影响，可能不会立即返还给操作系统。

CSS 的 `content-visibility` 也主要是渲染优化工具；单独使用它同样不能证明站点数据或组件状态被卸载。参考 [web.dev 的说明](https://web.dev/articles/content-visibility)。

## 展开策略

偏好结构为：

```json
{
  "enabled": true,
  "keepRecent": 1,
  "maxExpanded": 1
}
```

设置键为 `cgf.settings.v1`，存入 `chrome.storage.local`。输入需要归一化：

- `keepRecent` 为 0–5 的整数。
- `maxExpanded` 为 1–5 的整数。
- 默认展开数量不得大于同时展开上限。
- 缺失或无效的值回到安全的有效配置。

默认初始化时展开最新 1 条普通回答。用户主动展开旧回答后，策略按上限收起其他普通回答。一个回答可以通过自己的控制栏再次收起。

“普通回答”指没有生成、编辑或文字选区保护的回答。保护内容暂时独立于数量上限；这样不会因执行折叠策略而打断正在交互的回答。

## 保护条件与局限

| 条件 | 期望行为 | 需要真实页面确认的内容 |
| --- | --- | --- |
| 正在生成 | 暂时保持相关回答展开 | 生成标记和停止按钮的页面结构 |
| 正在编辑 | 暂时保留编辑区域及所属回答 | 编辑器、焦点和分支选择的结构 |
| 存在文字选区 | 保留包含选区的回答 | 鼠标、键盘、多节点选区及选区解除 |
| 未支持结构 | 不折叠原内容 | 页面结构变化后的可识别边界 |

保护可能使用站点属性、控件和 DOM 变化等信号；这些都不是对外稳定接口。保护识别不等于能理解所有页面交互，因此发布前需要按[测试说明](TESTING.md)进行真实页面验收。

## 更新与清理

内容脚本需要处理首次加载、动态插入、生成过程以及 SPA 内的对话切换。观察回调应合并短时间内的变化，避免每生成一个 token 就重新扫描、遍历或复制整个历史。

回答记录仅保留当前页面交互所需的引用与少量状态。回答被移除或页面切换时，应清理无效引用、观察关系和扩展控件，避免扩展成为新的长期内存持有者。

禁用扩展效果时应恢复原内容的可见性；扩展注入的属性和控件应有独立命名，避免覆盖原站样式和数据。

## 弹窗通信与当前页状态

内容脚本向弹窗提供识别数量、已折叠数量、展开数量、保护数量、未支持数量及启用 / 暂停状态。

内部消息约定：

```js
{ type: 'CGF_GET_STATUS' }
{ type: 'CGF_COMMAND', command: 'collapse-all' }
{ type: 'CGF_COMMAND', command: 'recent' }
{ type: 'CGF_COMMAND', command: 'restore' }
{ type: 'CGF_COMMAND', command: 'resume' }
```

`restore` 临时恢复当前页面并暂停折叠，便于原生搜索或排查；`resume` 继续按设置折叠。临时恢复不改变长期偏好。已关闭页面或没有内容脚本响应时，弹窗应提供可理解的状态，而不是假定命令成功。

## 权限与数据

- 仅声明 `storage` 权限。
- 内容脚本范围为 `https://chatgpt.com/*`。
- 不调用远程接口，不拦截聊天请求，不发送遥测。
- 不持久化正文、摘要、对话列表、会话令牌或消息 ID。
- 摘要只用于当前页的单行显示；不建立全文索引或完整聊天副本。

内容脚本工作在扩展的隔离 JavaScript 环境中，但共享页面 DOM；这种隔离不能让 DOM 修改自动获得兼容性保证。参考 [Chrome 内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)。

## 后续是否走向虚拟化

如果实测表明折叠已明显改善内存和滚动，可以先继续维护适配器和交互保护。如果主要内存仍被站点 JavaScript 状态和 DOM 持有，单纯增加折叠规则收益可能很小。

视口虚拟化的下一步必须先确定内容恢复来源、站点更新兼容性、滚动锚点以及查找体验。把节点挪到离屏 `DocumentFragment` 仍然保留节点对象，不能据此声称释放 DOM 内存；保存完整 HTML 字符串也可能增加新的内存副本。

下一阶段的判断依据应是同一真实对话上的测量结果，而不是“虚拟化”这个名称本身。

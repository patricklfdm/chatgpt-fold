# ChatGPT Fold

一个面向 ChatGPT 网页的轻量 Chrome 扩展。每条助手回答保留一行摘要，点击即可展开，再次点击可以收起。

**版本：0.1.5 · 修复思考期间误锁上一条回答**

本次修复新回答尚未出现时，上一条已完成回答被误标为“生成中”、无法操作的问题。浏览器回归使用真实 Chromium、合成页面和模拟 Chrome API，实际执行结果见 [VALIDATION.md](docs/VALIDATION.md)。使用者已确认 0.1.3 的闪现修复和 0.1.4 的展开状态保留有效；0.1.5 的实际页面效果仍需验收。

本项目优先限制同时参与渲染的回答数量。初始默认展开最新 1 条普通回答，同时展开上限默认也是 1；提高上限后，已有的展开选择会保留，超出时才收起最早展开的项。

## 0.1.5 更新

- 输入区出现停止按钮、ChatGPT 正在思考但新回答尚未出现时，旧回答保持原来的展开选择，展开 / 收起按钮仍可操作。
- 全局停止按钮只为已确认新增的回答提供生成保护，不再自动关联当前挂载的最后一条旧回答；滚动和历史重新挂载也不会转移这个保护。
- 生成结束或取消后清除关联，下一次请求重新确认目标。回答自身的明确生成标记仍独立生效，支持可识别的重新生成场景。
- 保留 0.1.4 的展开选择与数量上限规则。新增状态只有一个停止状态和一个目标标识，不缓存正文、HTML 或已卸载节点，也没有新增权限或网络请求。

仅有停止按钮时，扩展不能可靠判断一条已经存在的回答是否在生成。例如扩展启动 / 恢复时回答已经存在且只有全局 Stop、回答容器先于停止按钮登记，或原回答重新生成却没有自身生成标记时，会沿用普通展开策略，不猜测并锁住旧回答。详细边界见[生成保护说明](docs/ARCHITECTURE.md#无法仅靠停止按钮确认的情况)。

### 保留的 0.1.4 展开状态修复

- 有可靠消息身份的回答，在被站点卸载后重新挂载时，恢复原来的展开选择；滚动本身不重置选择，也不改变展开顺序。
- 新回答按默认最近数量加入展开项，不再重新设置所有旧回答。未超过上限时，之前展开的回答继续保持展开。
- 已被站点卸载的展开项也占用名额。超过上限时移除最早的展开选择；被收起或淘汰的项不会仅因再次滚入视野、或上限后来提高而自行打开。
- 仅修改同时展开上限时，保留仍在限额内的选择；点击“收起全部”“展开最近”、重新启用或切换对话等明确重置操作会重新应用对应策略。
- 跨节点保留的状态只包含少量消息标识和展开顺序，数量不超过设置上限，不保留旧 DOM、正文或 HTML 副本。新增展开状态回归，继续检查恢复时的第一帧。

例如上限为 3，A、B 已展开时，滚动往返后仍是 A、B；出现新回答 C 后保留 A、B、C。再展开 D 时，才收起其中最早展开的一项。临时生成、焦点和选区保护仍可以保持相关内容可见。

### 保留的 0.1.3 闪现修复

- 修复历史回答重新挂载后先显示全文、稍后才收起的问题。已启动的扫描器在观察到可识别的回答插入或显示状态变化时，直接完成折叠，不再等待 120 毫秒的发现批次。
- 移除对所有新挂载回答统一施加的 1.2 秒“更新中”展开保护。旧正文补齐、子树替换或消息标识变化也不再自动展开回答。
- 保留明确的生成、焦点、选区和未支持结构保护。普通文字更新只批量刷新摘要，不需要先显示全文。
- 页面卸载末尾回答或替换历史窗口时，不将历史窗口的最后一项自动当成最新回答。只保留一份末尾身份标记用于判断后续新增，不保存历史 DOM 或全文副本。
- 新增第一帧回归，覆盖历史挂载、正文更新、隐藏工作区激活、生成保护及暂停 / 禁用恢复。

此修复针对**扫描器已启动、页面已有可靠助手标记**时的历史内容更新。内容脚本仍在 `document_idle` 启动；首次打开页面、偏好尚未读取或页面尚未补齐作者标记时，不承诺绝对没有展开画面。无法可靠识别的内容继续保持可见。

### 保留的 0.1.2 页面适配

- 增加新版助手消息单元识别：两种搜索单元 key 的 `:assistant` 后缀，以及 `data-message-role="assistant"`。保留旧页面的识别规则。
- 对没有明确单元角色的内容，结合身份一致的消息标识容器与 `data-markdown-text-style="assistant-message"` 正文做保守补充识别；只有消息 ID 本身不能证明作者是助手，也不会把同一回答的多个正文片段分拆为多个折叠项。
- 排除明确用户消息、用户气泡和角色冲突。整个 `data-turn-key` / `data-talvt-turn-state` 容器可能同时包含提问与回答，不会仅凭这些属性折叠整个轮次。
- 排除隐藏工作区和演示时间线副本，处理显示状态切换；屏幕外但仍在当前活动文档中的回答、`display: contents` 容器仍可参与识别。
- 补充现代属性的增量观察、输入区内的 Stop 生成保护，以及诊断报告中的新版标记计数。没有新增站点权限、后台轮询或网络请求。

这次适配依据使用者提供的实际结构线索，以及公开适配项目作者记录的新页面结构。报告已确认选中的回答位于顶层聊天文档，并出现搜索消息容器与 turn 状态标记；它没有导出新版 key 的原始值。使用者随后确认识别和折叠正常工作，这不等于所有站点交互已完成验收。详细选择依据与来源见[架构说明](docs/ARCHITECTURE.md#页面结构与识别边界)。

### 保留的 0.1.1 修复

- 修复一类增量扫描遗漏：内层回答角色标记被移除，或回答子节点被删除后，重新检查存活的外层回答容器，避免已识别数量停在 0。
- 明确标有 `data-turn="assistant"` 的回答容器不再限于 `article` 标签；仍检查用户角色冲突并避免重复识别嵌套回答。
- 新增 **重新扫描** 和 **查看诊断 / 复制报告**，便于区分未匹配页面结构与扫描状态问题。
- 弹窗区分设置开启、扫描器未启动和未识别到回答，并在页面脚本版本过旧时提示刷新。

若更新后仍显示 0 条，请按下面的排查流程提供新版诊断报告；旧标记计数为 0 并不代表新版单元也没有被识别。

## 这个版本能做什么

- 为每条支持的助手回答添加摘要和展开 / 收起按钮。
- 初始化时默认展开最新 1 条回答；可以设置默认展开最近 0–5 条，新回答出现时按该设置加入已有选择。
- 限制记住的展开选择数量，范围为 1–5 条；已卸载的展开项也计入，避免滚动重置上限。
- 在同一对话中，凭可靠消息身份恢复被站点重新挂载的回答，保留原展开顺序。
- 识别新回答和单页应用内的对话切换，重新应用折叠规则。
- 暂时保留正在生成、正在编辑或包含已选中文字的回答；这些保护条件可以暂时超过展开上限。
- 在扩展弹窗中收起全部、展开最近回答，或临时恢复整个页面。
- 按需重新扫描当前页面，查看和复制仅含固定状态与计数的诊断报告。
- 只在本地保存偏好设置，不保存聊天正文，不上传数据，不加载远程脚本。

默认展开数量不能超过展开上限；保存设置时会将配置调整到有效范围。展开上限为 1 时，手动打开一条旧回答会让其他不受保护的回答收起。

## 内存优化的边界

初版通过 `display: none` 隐藏原回答的内容容器。浏览器无需继续为隐藏正文保留正常的布局和绘制结果；能否以及能节省多少内存，需要在真实对话上测量。

**原回答 DOM、ChatGPT 的 JavaScript 对象和 React 状态仍然存在。** 这个版本不会卸载原站组件，也不会把聊天正文序列化成副本。折叠后的 DOM 节点数量不会因此大幅减少，JavaScript 堆也不保证下降。

因此，初版的目标是减少同时显示的内容和渲染负担，不能保证解决所有长对话崩溃，也没有预设的“节省百分比”。如果页面主要占用来自站点自身的数据和组件状态，收益可能有限。详见[架构说明](docs/ARCHITECTURE.md)和[内存验证方法](docs/TESTING.md#内存验证)。

真实页面已有使用者的识别 / 折叠成功反馈，完整兼容性和内存对照仍待验收。网页结构变化可能影响识别；已识别但不支持折叠的结构会保留原内容，弹窗报告对应数量。如果页面完全没有支持的角色标记，弹窗显示已识别 0 条，扩展不会猜测并隐藏其他内容。

## 安装：无需 npm，也无需构建

要求 Chrome 109 或更新版本。

1. 下载并解压整个工程。
2. 在 VS Code 中选择 **文件 → 打开文件夹**，打开 `chatgpt-fold`；也可以打开工程中的 `chatgpt-fold.code-workspace`。
3. 在 Chrome 地址栏输入 `chrome://extensions`。
4. 打开右上角的 **开发者模式**。
5. 点击 **加载已解压的扩展程序**，选择包含 `manifest.json` 的 `chatgpt-fold` 根目录。
6. 刷新已经打开的 [ChatGPT](https://chatgpt.com/) 标签页。
7. 建议将扩展固定到工具栏，方便打开设置和查看状态。

安装前先暂时停用其他隐藏 / 折叠 ChatGPT 对话的扩展，以便确认本扩展的实际效果。完成独立测试后，再决定是否一起使用。

加载失败时先确认选中的是包含 `manifest.json` 的目录，而不是 ZIP 文件或其上一级目录。Chrome 官方的[加载未打包扩展说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)提供了相同流程。

### 日常使用

- **阅读回答：** 点击回答上方的摘要栏展开，再次点击收起。
- **默认策略：** 初始最新 1 条普通回答展开，其他回答折叠为一行摘要；达到上限后，新展开项替换最早展开的项。
- **保留选择：** 未超上限时，滚动往返和新回答到达不自动收起已有展开项。
- **修改策略：** 点击扩展图标，设置默认展开最近几条以及同时展开上限。
- **恢复查看：** 在弹窗中临时恢复本页；之后继续折叠，重新应用当前设置。
- **关闭扩展效果：** 在弹窗中关闭启用开关；已处理的回答恢复显示。

已识别为正在生成、编辑或包含文字选区的内容会受到保护。此时显示数量可能超过设置上限；保护解除后再由扩展重新评估。仅处于思考等待阶段时，已完成的旧回答仍可正常展开和收起。

弹窗中的数量统计对应当前已挂载的回答。被站点暂时卸载的展开项仍保留名额，但不计入当前 DOM 的“已展开”数量。无法确认消息身份时，扩展不会把另一条回答误当成原来的展开项。

### 搜索历史内容

Chrome 的原生 `Ctrl+F` / macOS `⌘F` 无法可靠搜索 `display: none` 隐藏的正文。

需要搜索整段对话时，先在扩展弹窗中选择 **临时恢复本页**，再使用浏览器搜索。查看完成后继续折叠。临时恢复期间会重新显示所有已识别正文，因此也会恢复相应渲染负担。

### 修改源码后更新扩展

1. 保存文件。
2. 打开 `chrome://extensions`，点击 ChatGPT Fold 卡片上的重新加载按钮。
3. 刷新 ChatGPT 页面，使新的内容脚本生效。

只重新加载扩展不会自动替换已经注入到旧标签页中的全部内容脚本。

### 更新到 0.1.5

1. 修复 PR 合并后，在 **Chrome 当前已加载的那个 `chatgpt-fold` 仓库目录**更新 `main` 分支，保持扩展安装路径不变。
2. 在 `chrome://extensions` 中点击 ChatGPT Fold 卡片的 **重新加载**。
3. **刷新 ChatGPT 标签页**，再打开扩展弹窗，确认版本为 **0.1.5**。
4. 发送新问题，检查思考阶段上一条回答仍能展开 / 收起，实际新回答出现后才获得生成保护；再验证取消和连续两次请求，详见[思考期间的生成目标](docs/TESTING.md#14-思考期间的生成目标)。同时检查[展开选择保留](docs/TESTING.md#13-保留展开选择与追加新回答)和[快速浏览历史回答](docs/TESTING.md#12-快速浏览历史回答)仍正常。

不要同时加载两份 ChatGPT Fold。若选择新的安装路径，应先停用旧的一份，避免两个实例同时处理页面。

首次安装也可使用仓库完整源码 ZIP。独立的结构诊断 `.js` 文件不是扩展安装包；后续更新以仓库 PR 为准。

### 已启用，但已识别为 0

先确认已刷新 ChatGPT 标签页、弹窗版本正确，并暂时停用其他隐藏或折叠对话的扩展。无需为了触发识别而再发送一条消息。

1. 点击 **重新扫描**。它会重新检查页面；如果当前处于临时恢复或关闭状态，不会自动开启折叠。
2. 仍为 0 时，点击 **查看诊断**，再点击 **复制报告**。复制不可用时，可以在报告框中手动复制。
3. 反馈这份报告、Chrome 版本和简单复现步骤即可；不需要复制整个页面 HTML 或对话正文。

从 0.1.2 起，报告的 `schemaVersion` 为 `2`，包含 `modern` 对象。报告只包含扩展版本、运行状态和固定页面标记的计数，不包含正文、摘要、页面 URL、消息 ID 或任意属性原值，也不会自动上传。常见读数可以帮助缩小范围：

| 读数 | 可以判断的范围 |
| --- | --- |
| 旧的两个原始助手标记为 0，但 `modern.searchUnitAssistantCount` 或 `modern.contentUnitAssistantCount` 大于 0 | 页面使用新版的明确助手单元；继续看可用候选与实际登记数量 |
| `modern.assistantBodyCount` 大于 0，但明确助手单元为 0 | 存在新版助手正文标记，需结合消息容器、角色冲突与隐藏状态判断是否可折叠 |
| 旧标记与新版助手标记都为 0 | 当前文档没有匹配到已支持的结构，仍需检查实际容器，不能仅凭 iframe 数量推断原因 |
| 有原始助手标记，但 `eligibleAnswerCount` 为 0 | 可能被角色冲突、嵌套或隐藏上下文规则排除；`modern.inactiveCandidateCount` 提供不可见候选计数 |
| `active` 为 `true`，`eligibleAnswerCount` 大于 0，但 `registeredAnswerCount` 为 0 | 页面存在可识别容器，仍有扫描或登记状态问题需要检查 |

这些读数用于定位，不代表已经确认某一种根因。各类标记可能位于同一条回答中，不能相加作为回答总数。关闭或临时恢复时，登记数量为 0 是正常的。

## 设置与权限

| 项目 | 默认值 | 含义 |
| --- | --- | --- |
| 启用 | 开启 | 对支持的 ChatGPT 回答应用折叠 |
| 默认展开最近几条 | 1 | 范围 0–5，决定初始化 / 重置，以及新到达回答的默认展开数量 |
| 同时展开上限 | 1 | 范围 1–5，约束保留的展开选择；超出时收起最早展开项 |
| 临时恢复本页 | 关闭 | 仅当前页面暂停折叠，便于搜索和排查 |

扩展仅声明 `storage` 权限，内容脚本仅匹配 `https://chatgpt.com/*`。不申请所有网站访问权限，不读取浏览历史，不调用模型接口，也不拦截 ChatGPT 的请求。

偏好保存在 `chrome.storage.local`。摘要和少量展开选择只用于当前页面运行，不作为聊天记录写入存储；刷新或切换对话会重新应用偏好。更多信息见[隐私说明](PRIVACY.md)。

### 开发检查

直接安装扩展不需要 Node.js；运行开发检查需要本机安装 Node.js 20 或更新版本。

```bash
npm test
npm run check
```

这两项检查不需要安装第三方 npm 依赖。`npm test` 使用 Node 内置测试运行器，入口是 `node --test tests/policy.test.cjs`，不依赖终端的通配符展开。

可选的 DOM 识别回归使用 Linkedom，在合成 HTML 上执行实际适配器代码：

```bash
npm install --no-save --package-lock=false linkedom@0.18.15
npm run test:dom
```

这项检查覆盖角色标记、嵌套与冲突过滤、扫描范围和诊断脱敏，不启动 Chrome，也不验证真实扩展注入、布局或当前 ChatGPT 页面。

可选的模拟页面浏览器测试使用 Playwright：

```bash
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

这项测试会下载开发用依赖和 Chromium；它不是运行扩展的必需步骤，也不能代替在真实 ChatGPT 页面上的手动验收。具体场景和验收清单见[测试说明](docs/TESTING.md)。

默认浏览器模式加载真实的未打包扩展。也可以运行 `npm run test:browser -- --mode=injected`，在真实 Chromium 中运行页面代码和 CSS，使用模拟 Chrome API。

针对历史挂载和展开选择的回归入口：

```bash
npm run test:paint
npm run test:state
```

两项均在合成页面中使用模拟 Chrome API，采样页面变化后的第一帧及后续短时间内的显示状态；断言期间不查询扩展状态或手动重扫，避免这些操作掩盖缺陷。`test:paint` 还检查思考阶段的按钮、生成徽标和目标关联；`test:state` 验证展开顺序、卸载后的名额、追加回答及明确重置。实际执行结果与各模式边界见[验证记录](docs/VALIDATION.md)。

## 已知限制与后续方向

- 此版本只处理助手回答，保留用户问题原样，暂不实现视口虚拟化。
- 原回答内容仍由站点保有；无法保证 JavaScript 堆或 Chrome 进程总内存按折叠数量同比下降。
- 页面选择器、生成状态和编辑控件会随 ChatGPT 更新，需要实测和维护。
- 助手正文之外的独立思考区或工具卡片可能不在当前折叠范围内。
- 展开选择只在当前页面、当前对话运行期间保留；刷新、切换对话或明确重置后重新应用偏好。
- 恢复展开需要可靠且唯一的消息身份。仅有位置型 unit key、身份冲突或没有消息 ID 的新节点，无法保证恢复原选择，可手动展开；不会保存全文来猜测同一条回答。
- 无法可靠确认最新回答身份时，不自动把历史窗口末尾当作新回答展开；“展开最近”可以按当前已挂载内容重新应用偏好。
- 绘制前折叠依赖已启动的观察器和可靠的助手标记；冷启动或尚未可识别的 DOM 不在本次保证范围内。
- 原生搜索需要先恢复正文；某些富交互内容、嵌套滚动区域和其他扩展可能需要额外适配。

下一步应先在你的典型长对话中记录真实收益和兼容性结果，再决定是否继续做视口虚拟化。优先验证的指标是 Chrome 任务管理器内存、JavaScript 堆、DOM 数量和滚动响应，而不是仅凭页面变短判断优化成功。
